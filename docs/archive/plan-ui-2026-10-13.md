# Liapoldus Studio — план переработки UI и целевая архитектура

> Статус: утверждённый план реализации. Описывает целевую архитектуру Studio
> после UI-переработки. Синхронизирован с `TODO.md`; не заменяет контракты Core,
> Plugin SDK и `pluginprotocol`.

## 1. Цель

Переработать desktop-оболочку Studio в модель, близкую к Zed/Figma:

- убрать встроенный текстовый редактор и все CodeMirror-зависимости;
- заменить state-навигацию (`screen: NavItem`) на tabbed workspace;
- собрать Zed-style top bar (frameless окно, нативные traffic lights на macOS,
  свои кнопки на Windows/Linux);
- переписать правый Inspector в schema-driven property editor уровня
  Figma/Unity (settings + полный link contract + info + actions);
- заменить нижний Dock на вкладки `Problems` / `Output` / `Reports`;
- разрешить sandboxed iframe-вкладки для UI Studio-плагинов (кнопки запуска в
  левом рейле).

Результат: Studio остаётся отдельной desktop-средой разработки (файлы, Git,
отчёты CLI), не становится Core-клиентом и не грузит runtime-плагины.

## 2. Принятые решения (зафиксировано)

| Тема | Решение |
| --- | --- |
| Оконная рамка | `Frameless` + кастомный top bar. macOS — нативные traffic lights (`Mac.TitleBarHiddenInset()`), Windows/Linux — свои 3 кнопки слева (закрыть/развернуть/свернуть). Top bar — drag region. |
| Модель workspace | `workspace = проект/папка` (модель Zed). Переключатель workspace = переключатель проекта. |
| Home / Settings | Только в top panel. Home — стартовый экран без проекта. Settings — глобальная полноэкранная страница (не вкладка). |
| Разделы Settings | Editor (внешний), Appearance (тема), Language, Toolchain/CLI, Local Core. |
| Редактор | Встроенный редактор удаляется полностью. Открытие файла — одиночный клик → внешний редактор. Настройка: OS default + глобальный редактор + per-mask ассоциации. |
| Навигация | Всё — вкладки. Левый activity rail остаётся, но его кнопки открывают/фокусируют вкладки. |
| Вкладки | Закрываемые, drag-reorder, персистятся. Без pin. Новая схема `workspace/v3`. |
| Inspector | schema-driven Settings + полное редактирование Link contract + Info-секции (identity/source/last deploy/links/context) + действия Run/Logs/Inspect. |
| Нижний Dock | Удаляется. Его содержимое → вкладки `Problems`, `Output`, `Reports`. |
| Plugin iframe | Разрешён sandboxed iframe для UI любого установленного Studio-плагина. Всегда строгий sandbox. Запуск — кнопками в левом рейле. |
| Go file API | `ReadProjectFile` / `WriteProjectFile` удаляются. |

## 3. Целевая оболочка (shell)

```
┌───────────────────────────────────────────────────────────────────────┐
│ ● ● ●   [Home] [Settings]  │  <project> ▾   │   tabs…            [logo] │  TopBar (drag)
├───────────────────────────────────────────────────────────────────────┤
│ [Canvas][Files][Git][Reports][Plugins][Artifacts][Runtime] │ [Problems] │  TabStrip
│ [Output] │ plugins…                                                    │
├──────┬────────────────────────────────────────────────────┬───────────┤
│ rail │                Workbench (active tab)               │ Inspector │
│      │                                                    │           │
└──────┴────────────────────────────────────────────────────┴───────────┘
```

- **TopBar** монтируется всегда (frameless требует постоянных window controls и
  drag region). Workspace-switcher и TabStrip показываются только при открытом
  проекте; в Home/Settings скрыты.
- **Workspace switcher**: recent projects, открыть проект, создать проект,
  путь/действия проекта. (Пункт «закрыть проект» заменён на действия проекта.)
- **TabStrip**: активная рабочая вкладка, закрытие, drag-reorder, горизонтальный
  скролл. Вкладки персистятся в `.studio/workspace.json` (`workspace/v3`).
- **Левая rail**: кнопки-открыватели вкладок: Canvas, Files, Git, Reports,
  Plugins, Artifacts, Runtime, Problems, Output, далее — кнопки iframe-surfaces
  установленных Studio-плагинов. Плагинные кнопки отделены разделителем.
- **Home** — стартовый экран при отсутствии активного проекта (recent, open,
  create, toolchain status).
- **Settings** — глобальная полноэкранная страница в области контента (top bar
  остаётся). Разделы: Editor / Appearance / Language / Toolchain & CLI /
  Local Core.

## 4. Model / state

### Frontend (`frontend/src/models/studio.ts`)

Заменяем `screen: NavItem` + `documents`/`activeDocument` + dock на tabbed-модель:

```ts
type TabKind =
  | 'canvas' | 'files' | 'git' | 'reports' | 'plugins'
  | 'artifacts' | 'runtime' | 'problems' | 'output'
  | 'studio-plugin';

interface Tab {
  id: string;
  kind: TabKind;
  title: string;
  pluginId?: string;   // для kind === 'studio-plugin'
  surfaceId?: string;  // id surface внутри плагина
}

interface WorkspaceSnapshot {
  schemaVersion: 'workspace/v3';
  activeTabId: string | null;
  tabs: Tab[];
  layout: LayoutState;
}
```

- `view: 'workspace' | 'home' | 'settings'` заменяет навигационный `screen`.
- Удаляются: `DocumentState`, `documents`, `activeDocument`, `dock*`, `openFile`
  контроллера, `Cmd/Ctrl+S`.
- Сохраняются: `selected` (plugin/link), canvas nodes/edges, `runtimeStatuses`,
  `layout`.
- Восстановление схемы fail-closed: неизвестная версия — сброс к default
  (`workspace/v3`), а не частичный merge.

### Legend: canonical vs runtime

- Вкладки — суть UI-состояние Studio, не Core-состояние. Персистятся только
  локально, в `.studio/workspace.json`.

## 5. Inspector

Секции (collapsible), для plugin-узла и для link-узла:

1. **Identity / Info** — read-only: id, name, service, version, manifest, source.
2. **Settings** — schema-driven форма по JSON Schema (draft 2020-12) из
   `readProjectSchema`; существующий backend validation/merge/redaction
   переиспользуется. Секреты — только redacted (secret-ref), raw values не
   ходят во frontend.
3. **Link contract** — полное редактирование link-полей (см. §6).
4. **Source binding** — где в проекте определён plugin/link (path, module ref).
5. **Last deploy** — последний импортированный CLI/Core report (redacted).
6. **Context** — project, Git revision/branch.
7. **Actions** — Run / Restart / Logs / Inspect (typed CLI intents, ephemeral
   status; при недоступности CLI/Core — `unknown`).

Schema-renderer (новый `frontend/src/ui/schema/`) поддерживает типы:
`string`, `number`, `boolean`, `select`, `multiselect`, `duration`, `size`,
`file`, `dir`, `array`, `object`, `secret-ref`. Неизвестный тип поля →
секция помечается `unavailable` (fail-closed), без угадывания.

## 6. Link contract (backend)

Полное редактирование link contract требует нового typed Go-пути:

- `internal/domain/interfaces/project.go` → `GraphRepository` добавляет
  `UpdatePluginLink(...)`.
- `internal/infrastructure/project/mutations.go` → реализация мутации с
  валидацией и atomic write.
- `internal/presentation/wails/app.go` → binding.

Поля link contract (редактируемые, без raw secrets): методы/transport,
timeout, retry policy, limits, securityProfile, compatibility,
redactionPolicy, disabledMethods, schema paths.

## 7. Plugin iframe host

- Манифест Studio-плагина (owned другим репозиторием) получает декларацию
  UI-surface. Пока используется существующее неиспользуемое поле
  `PluginSurface.Route` (`internal/domain/models/plugin.go`).
- Studio host отдаёт ассеты плагина по path-confined маршруту через Wails
  `AssetServer`; HTML/JS никогда не отдавались через Go-host раньше — это новое
  поведение, ограниченное строгим sandbox.
- Frontend: `PluginSurfaceFrame` — `<iframe sandbox="allow-scripts">`
  (без `allow-same-origin`, без `allow-popups`, без forms), строгий CSP
  `frame-src`, обмен только через `postMessage` bridge.
- Никакого доступа iframe к Wails bindings / Node / filesystem.
- Запуск iframe-вкладок — кнопки в левой rail.

> Граница: контракт декларации UI-surface принадлежит plugin SDK /
> `pluginprotocol` (другой репозиторий). Пока Studio строит iframe на
> существующем `surface.route` как промежуточный вариант; финальный контракт
> требует отдельного согласования.

## 8. Оконная интеграция (Go)

- `main.go`: `Frameless`, `Mac.TitleBarHiddenInset()`, `MinWidth`/`MinHeight`,
  `AssetServer` handler для ассетов plugin-surface.
- Frontend рисует drag region и (Win/Linux) собственные window controls.

## 10. Фазы реализации

### Phase 0 — Governance & docs
- Обновить `AGENTS.md`, `docs/*`, `README.md`, `plan.md`, `TODO.md`.
- Зафиксировать TODO на изменение pluginprotocol/plugin SDK в их репозитории.

### Phase 3 — Inspector

- Обновить/добавить тесты.
- `npm test`, `npx tsc`, `npm run lint`, `make check`, `make check-race`,
  `make desktop-build`.

## 11. Верификация

Каждая фаза завершается зелёным gate:

```sh
GOWORK=off GOFLAGS=-p=1 make check
make check-race
make desktop-build
```

Плюс smoke `wails dev` (Vite + dev server + рендер). Никаких baseline, path
exclusions или inline disables ради PASS. Bindings fail-closed: изменение схемы
→ обновить adapter/тесты → `npm run bindings:prepare` → `bindings:check`.
